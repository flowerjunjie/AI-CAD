## 一、AI / Agent / 大模型

| 词 | 大白话（面试这么说） |
|---|---|
| **LLM** | 大语言模型。我项目里 LLM 只干"理解设计师说话的意思"，**不碰规范判断**——规范是写死的代码。这是我把 LLM 和规则引擎分家的核心。 |
| **RAG** | 检索增强生成。把规范条文/历史图纸喂进向量库，问问题时先检索相关条文再让 LLM 答，**降低幻觉**。我用本地 ChromaDB 存，数据不出境。 |
| **ChromaDB** | 本地向量数据库，轻量，不用外部服务。设计院图纸涉密，本地存最稳。 |
| **MCP** | Model Context Protocol，**AI Agent 跟工具（比如 CAD）交互的标准协议**。Autodesk 2025 开始推这个，我是按这个方向做的。 |
| **LangGraph** | 一个建 AI Agent 流程的框架，**把流程画成图**，每个节点可暂停、可观察、可改。我选它是为了"人在回路"——设计师能在任意节点介入改数据，Agent 接着跑。 |
| **LangChain** | 更偏"调 LLM 接口"的框架。LangGraph 是它上面专门管"带状态的流程"的。我只用了 LangGraph，没用它整个包。 |
| **幻觉 / 置信度** | 幻觉=AI 一本正经说错话。置信度=我对一个数值敢不敢拍板的程度。回填规范时我**分 low/medium/high 标注置信度，查不到条文就不虚标高**——这是我对"对结果负责"的态度。 |
| **人在回路 (human-in-the-loop)** | 不是全自动，**AI 跑到关键节点停下来等设计师确认**。改完才继续。设计院的图出错了要签字，所以这必须是设计原则不是装饰。 |
| **checkpointer / interrupt** | LangGraph 里的暂停机制。checkpointer 存中间状态，interrupt 让流程挂起等外部确认，恢复时接着跑。我的人在回路就靠这俩。 |
| **TypedDict / State** | LangGraph 节点之间传的状态容器。设计师改的是状态里的数据，**不用碰 Python 代码**——这是"设计师能改"的实现基础。 |

## 二、CAD / 图纸（AI-CAD 主战场）

| 词 | 大白话 |
|---|---|
| **DWG / DXF** | 都是 AutoCAD 图纸格式。DWG 是二进制官方格式，DXF 是文本交换格式。ezdxf 主要读写 DXF。 |
| **ezdxf** | Python 库，读写 CAD 文件，**不用装 AutoCAD、跨平台**。我拿它当只读解析层。 |
| **COM 接口** | Windows 上控制 AutoCAD 的自动化接口，能**直接写 AutoCAD 原生格式**。我拿它当写出层。 |
| **双引擎** | ezdxf 读 + COM 写。没装 AutoCAD 时 ezdxf 也能解析，装了时 COM 原生写回。**互为 fallback**，不锁死。 |
| **图层 (layer)** | CAD 里把同类图元分图层管理（墙一个层、管一个层、标注一个层）。我 5 个专业各占独立图层，互不混。 |
| **LWPOLYLINE / LINE / ARC / INSERT** | CAD 图元类型。LWPOLYLINE=多段线（我画墙体/管线用它），LINE=直线，ARC=弧线（门扇），INSERT=块引用（门窗/柱用）。 |
| **ATTRIB** | 块上的属性文字（比如插座的安装高度写在块属性里）。我从这读数值喂给规则引擎。 |
| **HATCH** | 图元填充（画斜线/实心阴影）。我出图深化时给梁加了截面填充。 |
| **线型 / 点划线 / 虚线** | CAD 制图惯例：墙粗实线、轴网点划线、管道虚线。我出图深化时按惯例分了线型，不是全画实线。 |
| **DWG 双引擎 fallback** | 复杂图元 ezdxf 解不动时，COM 或人工兜底。AI 不硬猜解不开的。 |
| **BIM / Revit / Dynamo** | BIM=建筑信息模型（3D+数据），Revit=BIM 软件，Dynamo=Revit 上的可视化编程。我项目走的是 **CAD 施工图深化不是 BIM**，定位要分清。 |
| **VBA / LISP** | AutoCAD 二次开发的两种语言。我招 CAD 开发优先找会这个的。 |
| **Autodesk** | AutoCAD 的母公司。它 2025 开始推 MCP，AI+CAD 是行业共识方向。 |

## 三、医疗（两段项目举证）

| 词 | 大白话 |
|---|---|
| **ICU / OICU** | 重症监护病房 / 产科重症监护病房。我那两套系统的场景。 |
| **PHI / PII** | 受保护健康信息 / 个人身份信息。医疗系统**红线**，我两套系统都做到 100% 合规审计通过。 |
| **PRD** | 产品需求文档。我自己能写——这是技术负责人"产品能力"的举证。 |
| **Axure** | 画原型图的软件。我能用它出原型。 |
| **HL7 FHIR** | 医疗数据交换的国际标准（像医疗界的 HTTP）。我用 icu-fhir 模块做设备/系统对接。 |
| **HL7 / DICOM** | HL7 管临床数据交换，DICOM 管医学影像（CT/DR）。设备对接绕不开这两个。 |
| **MES** | 制造执行系统。我在金煤智能做的那套智能制造平台（智能制造那段经历）。 |
| **HLS / CDN** | HLS=视频流媒体协议，CDN=内容分发加速。在线教育那套我用的，视频加载提速 70%。 |

## 四、后端 / 架构 / 数据

| 词 | 大白话 |
|---|---|
| **微服务** | 把一个大系统拆成多个独立服务（商品、交易、结算各一个），能独立部署。电力交易我从单体拆成 8 个。 |
| **Spring Boot / Cloud** | Java 后端框架 / 微服务全家桶。我的后端主力技术栈。 |
| **Spring Cloud Gateway** | API 网关，微服务对外统一入口。产科 ICU 用它。 |
| **Kafka** | 消息队列/事件总线。产科 ICU 里"预警→抢救"靠它解耦：预警引擎发事件，抢救、科研各订阅，**加个订阅方不用改老链路**。 |
| **ZooKeeper** | 分布式协调/注册中心，管服务发现和配置。产科 ICU 基础设施。 |
| **TDengine** | 时序数据库。**生命体征一天几百万条，普通 MySQL 扛不住**，我专门用 TDengine 存时序——这是"存储模型匹配数据形状"的判断。 |
| **MySQL / Redis** | 关系型主库 / 缓存+会话。业务数据进 MySQL，热数据/会话进 Redis。 |
| **OpenTelemetry (otel)** | 全链路可观测（追踪/指标/日志）。产科 ICU 接了它，排障能追到每一次调用。 |
| **K8s / Docker** | 容器编排 / 容器化。我的医疗系统生产部署走这套。 |
| **actuator / 健康检查** | Spring 自带健康探针，K8s 用它判断服务活着没。 |
| **JWT** | 认证令牌（无状态登录）。产科 ICU 的认证服务用它。 |
| **RESTful / API** | 接口风格 / 应用接口。我说的"端点"就指这些。 |
| **CQRS / Event Sourcing** | 读模型和写模型分离 / 用事件日志重建状态。我简历里写的架构模式，被问到能说清"什么场景用、什么场景不用"。 |
| **高并发 / 响应时间 / 可用性** | 我能报数：**并发 1500→5000+、核心接口响应 <200ms、可用性 99.9%**（电力交易实测值，别记错）。 |
| **CI/CD** | 持续集成/持续部署。金煤智能那套我把发布从每月 1 次提到每周 3 次。 |
| **Nginx** | Web 服务器/反向代理。我部署用。 |
| **Go 网关** | 产科 ICU 的设备协议网关用 Go 写——**多路设备协议解析、长时间稳定跑、内存可预测**，这活儿 Go 比 Java 合适。 |

## 五、面试高频"黑话"防卡壳

| 词 | 一句话接得住 |
|---|---|
| **MVP** | 最小可用版本。我主张先做一个专业做深做透，不贪五个一起上。 |
| **护城河** | 我的护城河是**规则库越用越值钱**（设计院自己写规范条目），不是技术壁垒是知识资产壁垒。 |
| **降本 / 边际成本** | 一个专业做透后，复制到下一个专业的成本会降——这是我分阶段的依据。 |
| **落地 / 闭环** | 落地=真能跑不是 PPT。闭环=每个输出有人确认、可追溯，AI 不直接出图。 |
| **对齐 / 拉通** | 我跟设计师对齐验收标准，把技术决策和业务方拉通。 |

## 考前 5 分钟 · 只背这几条（最容易卡壳的）

1. **MCP** = AI 跟 CAD 交互的标准协议，Autodesk 在推 → 我知道行业方向
2. **人在回路** = 每个节点停下等设计师确认，AI 不直接出图 → 这是设计原则
3. **双引擎** = ezdxf 读 + COM 写，互为 fallback → 不锁死 AutoCAD
4. **TDengine** = 时序库，体征数据专用，MySQL 扛不住 → 存储匹配数据形状
5. **Kafka** = 消息总线，解耦"预警→抢救" → 加订阅方不改老链路
6. **置信度 low/medium/high** = 查不到条文不虚标高 → 我对结果负责
7. **PHI/PII 100% 合规** = 医疗系统红线，我两套都过审计
8. **护城河 = 规则库** = 设计院越写越值钱，知识资产壁垒
