## Phase 1：建筑专业 MVP（第3-8周）

### 目标
跑通住宅套型施工图深化全流程，每步人工确认。

### 核心功能

| 模块 | 功能 | 优先级 | 负责人 |
|------|------|--------|--------|
| 方案输入 | 接收PDF/图片方案，自动识别户型轮廓 | P0 | 后端 |
| 墙体生成 | 基于识别结果生成墙体图元（含厚度标注） | P0 | CAD开发 |
| 门窗插入 | 按规范自动插入门窗图块（带编号） | P0 | CAD开发 |
| 尺寸标注 | 自动生成轴线标注、洞口标注 | P0 | CAD开发 |
| 材料表生成 | 自动生成门窗表、墙体材料表 | P1 | 后端 |
| 规范初检 | 检查：门宽≥0.9m、窗台高度≤0.9m等硬性规则 | P0 | 后端 |
| 人工确认界面 | 每个步骤暂停，设计师确认/修改 | P0 | 前端 |

### MVP 场景
- 选择 1-2 个真实住宅户型作为测试样本
- 全流程跑通：方案输入 → 墙体 → 门窗 → 标注 → 规范检查 → 导出

### 验收标准
- 能处理标准住宅户型（2-3个房间）
- 规范检查准确率 100%（硬性规则）
- 人工确认环节正常触发

## Phase 2：规则引擎完善（第9-14周）

### 目标
规则 DSL 化，支持设计师自行编辑规则，无需改代码。

### 核心功能

| 模块 | 功能 |
|------|------|
| 规则 DSL | 将规范条文写成可执行代码 |
| 规则编辑器 | 设计师可以自行添加/修改规则 |
| 批量校验 | 全图纸一次扫描，输出问题清单 |
| 修改联动 | 修改一处，关联标注自动更新 |
| 版本对比 | 每次修改生成diff，可回溯 |

---

## Phase 3：第二专业接入（第15-22周）

### 目标
接入给排水或电气中规则更明确的一个专业。

### 选择标准
- 规范条目化程度高
- 容易验证正确性
- 与建筑专业冲突较少

### 候选专业
- 给排水：管径、坡度、间距规则明确
- 电气：插座位置、开关高度规则明确

---

## Phase 4：多专业协调 + 团队搭建（第23周起）

### 目标
实现多专业碰撞检测，组建完整研发团队。

### 核心功能

| 模块 | 功能 |
|------|------|
| 统一坐标系 | 建筑/结构/水电在同一坐标空间 |
| 碰撞检测 | 自动检测管线穿梁、插座撞梁等冲突 |
| 团队权限 | 多设计师协作，改动冲突检测 |

### 招聘计划
- 后端工程师 × 2
- CAD 开发 × 1
- 前端工程师 × 1
